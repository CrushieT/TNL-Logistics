## Native Disconnect and Multi-Device Contention Handling

- **Contention Root Cause:** The original `react-native-bluetooth-escpos-printer` module had no native `disconnect` method exposed to React Native. While the application cleared JavaScript state (`connectedDevice = null`), the underlying RFCOMM `BluetoothSocket` and `ConnectedThread` remained active on the phone. Because thermal label printers (Bluetooth Classic SPP) permit only one active client connection, a second device attempting to connect was rejected with `Unable to connect device`. In addition, if Phone 1 abruptly turned off Bluetooth without closing the socket first, the printer's onboard Bluetooth MCU was left waiting for Link Supervision Timeout or in an unresponsive socket state.
- **Native Disconnect Method:** Patched `RNBluetoothManagerModule.java` with `@ReactMethod public void disconnect(String address, final Promise promise)`. It cancels any pending connection promise, calls `mService.stop()` to send an RFCOMM DISC frame and close the socket, resets `mConnectedDeviceName`, and resolves `true`.
- **Contention Error Guidance & Retry:** Updated `RNBluetoothManagerModule.java` to reject with `EVENT_UNABLE_CONNECT` and descriptive contention guidance: `"Unable to connect to printer. The printer may be connected to another device or out of range. Disconnect other devices or restart the printer."`. Updated `bluetoothPrinterService.js` to match `EVENT_UNABLE_CONNECT` and error messages containing `Unable to connect` so the single 500 ms cleanup pause and retry properly execute.
- **Verification:** 4 targeted regression tests in `printer.test.mjs` and `bluetoothNativeScan.test.mjs` verify native disconnect invocation, empty address handling, error matching, and Java socket teardown.

## Scoped merge review

Correctness: The plugin preserves unrelated permissions and is idempotent; tests cover duplicates, missing declarations, flags, and caps. Native scans reject overlap before replacing shared state and clear their promise before fallback or failure. A 45-second native deadline handles a missing completion broadcast, with explicit permission or Bluetooth-off failures and single settlement. A late deadline or discovery broadcast cannot settle a replacement scan. Scan promises and deadlines are owned by each native module instance, and bridge shutdown clears its pending scan and listeners. The UI keeps paired devices selectable while leaving connection and reachability to the explicit Connect action. Component checks cover notice clearing, timeout recovery, mode changes, connection failure, and no print/audit side effects.

Readability and architecture: The permission rules live in one Expo plugin and one release validator; the service owns runtime requests and response normalization; the context owns notice state. No backend, web, dependency, or label-command changes were introduced. The patch retains the library's prior build and AndroidX changes.

Security and performance: `neverForLocation` is limited to printer discovery, with Location capped at API 30; no Bluetooth data is used to infer location. No unbounded work, new network calls, or print-audit writes were added to scanning. Native and UI single-scan guards prevent one scan from replacing another. No critical or high code finding remains in the scoped review. The only acceptance limit is physical radio behavior and the signed APK manifest, which the local build did not test.
